## 一、核心设计原则（来自多轮实测与 23 条 Ryugi 批注沉淀）

1. **先用 Ryugi 定设计稿，再落代码**：避免直接做 PoC 返工；设计稿必须携带丰富、多状态、多格式的真实 Mock 数据，才能真实评估交互。
2. **使用者视角，而非系统内部实现视角**：
   - 消灭「需要注意 / 运行中 / 已结束」等机械字面状态标签与数字角标轰炸；
   - 消灭所有「自解释型小字文案」（如「仅展示机器名」「自动匹配本机 `~/.ssh/config`…」）——交互本身符合直觉，就是为了省掉解释。
3. **减噪音，不减有效引导**：
   - 在已有上下文的页面（总览、已进行的会话输入框、工具菜单）保持极致克制甚至留白；
   - 在空白起点（新建线程页）保留轻量、不抖动的人话定位引导与可点击起手词，让人一眼知道每个模式能做什么。
4. **低刺激单槽状态语言**：全站行尾只有一个固定 `14×14` 状态槽（`StatusMark`），文字只进 `title` / `aria-label`：
   - 优先级：`failed`（暗红警示标 + 左 2px 暗红竖线）> `needs-you` / `approval`（强调色 Hand 标 + 左 2px 强调竖线）> `running`（3×3 低饱和静态点阵，不闪烁）> `ready`（6px 克制蓝点，进会话读完即消隐）> `resting`（纯留白，不画任何灰点）。

## 二、三类内容的清晰边界（不再混为一谈，也不焊死二选一）

| 类别 | 定位与生命周期 | 典型内容 | 在界面中的落点 |
|---|---|---|---|
| **对话内嵌媒体 / 附件** | 随对话流一次性消费 | 图片、架构示意图、截图、临时文件 | **直接在对话消息流中展示或下载**，不强行塞入 Artifacts |
| **Artifacts（全局可复用）** | Agent 判断具有**反复复用价值**、需要跨会话长期管理的内容（参考 Anthropic Artifacts） | 方案 Markdown、PPT 演示稿、Word 文档、表格、Ryugi 交互画板等（可扩展注册新预览器） | ① 左侧一级导航全局 **`Artifacts`** 列表；② Session 标题旁紧凑 **Artifact 图标**（点击先弹出本会话及子会话的 Artifacts 列表再选看）；③ 回复下方按需呈现卡片 |
| **Source Review（项目级 Checkpoint Diff）** | **跟随项目工作区**，始终展示相对上次 **Checkpoint** 的增量代码 Diff，不是某个 Session 的一次性静态产物 | Git Worktree 代码变更 | ① Session 顶栏右侧直接显示实时 Diff 入口（`+218 −64`）；② 点一下直进 Source Review 模式；③ 审阅无误点 `✓ Checkpoint` 即推进为一个完成的 Checkpoint |

## 三、逐页与核心组件决策规范

### 1. 左侧主导航 & 全局空间底部（`Home LAN`）
- **一级导航**：`总览` · `PA / Hebi8` · `Artifacts` · `新建线程`（无数字角标）。
- **项目树**：项目 → 主线程（子会话按 [subsession-ux-v4-spec.md](./subsession-ux-v4-spec.md) 方案 A 使用左侧留白槽轻箭头折叠），每行仅右侧一个 `14×14` `StatusMark`。
- **左下角工作区状态**：
  - 展示**全局可配置空间名**（如 `Home LAN`，不绑死单台机器名），加状态圆点与延迟。
  - 点击展开弹窗，**节点列表默认展开**；**只突出机器名本身**，去掉括号角色说明文案；仅当前客户端节点挂极弱 `本机` 标识。
  - **用颜色提供在线延迟与离线区分度**：低延迟绿色（如 `11ms`）、中高延迟琥珀色（如 `92ms`）、离线灰色空心点 + 离线时长。
  - 弹窗只聚焦网络整体状态与节点列表，底部仅保留安静的「网络与节点设置」入口（不塞调试控件或 IDE 下拉）。

### 2. 总览页（Home · 桌面 & 移动端）
- **只看状态与是否需要介入，拿掉「看产出」直跳**：自然动线是 `扫总览状态 → 进会话先读回复结论 → 再决定是否展开 Source Review 或 Artifacts`。
- **紧凑标题列表，去掉二行会话摘要**：桌面端与移动端总览均不显示额外摘要文本，避免零理解增益的视觉开销；单行保留 `标题 + 项目名 + 时间 + 行尾 StatusMark`，按 `等你处理` / `刚完成 · 未读结果` / `进行中` / `最近` 分组。

### 3. PA 助手页
- 与总览页形成清晰分工：总览是极简标题索引；PA 对话页则是**围绕用户具体提问做上下文相关性提炼**——不是机械转述各个 Session 的状态，而是站在当前问题（如「今晚发版有哪些会卡住」）出发，过滤无关线程、只优先呈现相关会话卡片与为什么相关的行动建议。

### 4. 新建线程页（New Thread）
- 顶层 `任务 / 问 PA / 对话` 三 Tab 切换保证 **`0.0px` 零抖动**（固定标题区高度）。
- 保留**一句话模式定位说明**与 **3 条可点击起手词**，让用户打开时能直观知道每个模式能做什么。
- 提交按钮同样使用纯图标按钮（无冗余文字）。

### 5. Session 会话页
- **顶部 2 行紧凑顶栏**：
  - 左侧第 1 行：`Session 标题` + **紧凑 Artifact 图标**（含本会话及子会话产出的 Artifacts；**点击先弹出列表选择**，不直接盲跳预览）+ `StatusMark`。
  - 左侧第 2 行：极简微元行（`项目名 · 主机 SSH 别名 · 分支`），当前会话归属一眼可见。
  - 右侧：
    1. **IDE 打开按钮（自动本机 / SSH 别名机制）**：使用**各 IDE 专属图标 + `ssh 主机别名`**（本机工作区时为 `图标 + 编辑器名`）；下拉菜单仅保留干净的编辑器图标列表（`Cursor / VS Code / Antigravity / Zed / 终端` 等），**零自解释头尾文案**。
    2. **实时 Diff 入口**：直接显示 `+218 −64`，点击直进 Source Review。
    3. **子会话紧凑计数入口**（有子会话时显示，详见 [subsession-ux-v4-spec.md](./subsession-ux-v4-spec.md)）。
- **底部输入框（Composer）**：
  - **输入框顶部**：存在待发 Review 评论时，以和附件文件同形态的紧凑胶囊提示 **`💬 N 条 Review 批注`**，让用户一眼感知发送会一并带上这些批注（正文留空也可直接发出）。
  - **Placeholder**：空闲态完全**留白**；仅在模型运行中提示极简快捷键 **`Enter 入队 · ⌘↵ 立刻插入`**。
  - **底栏运行时信息**：明确展示并可切换当前会话的 **Agent / 模型 / Effort / 权限**。
  - **发送按钮纯图标化（无文字）**：仅用图标与视觉状态传达 Session 状态和可发送性：
    - 空闲 + 无内容：弱化禁用态 `↑`
    - 空闲 + 有输入（或带待发批注）：高亮实心 `↑`
    - 运行中 + 无输入：停止方块 `■`
    - 运行中 + 有输入：入队图标 `↳` / 队列发送标

### 6. 分栏审阅浮层（Source Review & Artifacts 共用）
- **固定双栏**：左侧主内容（~62%），右侧始终是当前实时 Session 对话（~38%）。
- **单标题下拉切换（取消顶部横向 Tab）**：左上角只显示当前查看对象的名称 + `▾`，点击下拉在 **`代码`（`Source Review`）** 与 **`Artifacts`** 之间切换；顶栏与下拉中不重复堆砌冗余的「相对上次 Checkpoint」文案，仅在 Source Review 右上角保留简洁的 **`✓ Checkpoint`** 确认按钮。
- **彻底取消底部全量批注占位条**，把完整垂直视口还给代码与文档：
  - **Code Diff 文件树**：有评论的文件行尾直接标 `💬 N`；文件树左下角留一个默认收起的轻量入口（`💬 N 条待发评论 ▴`），按需展开跳转。
  - **PPT 幻灯片**：底部缩略图角标直接显示 `💬 N`。
  - **Markdown / Word / 设计画板**：评论就地锚定在段落或画板下方。
- **GitHub PR Review 风格代码批注**：
  - 支持**多行选区**（点击/Shift 选行段如 `L39–L45`）与**行内文本选区**（拖选代码词段弹出评论触发器）。
  - 已添加的评论卡片**直接内联渲染在选中行下方**（带高亮行背景或词段高亮，标 `Pending` 态），并在右侧对话输入框顶部同步反映待发批注胶囊。

## 四、工程落地与对齐原则

1. **后端协议支撑**：
   - 项目/Worktree 级 `Checkpoint` 游标接口，支撑 `Source Review` 实时计算相对上次 Checkpoint 的增量 Diff 及 `POST .../checkpoints` 推进；
   - 全局 `Artifacts` 索引表与列表 API（区分对话内嵌附件 vs 可复用 Artifacts，支持按类型扩展渲染器）；
   - Review Comments 锚点支持 `startLine..endLine` 与可选 `selectedText` / `slidePage` / `sectionId`。
2. **Ryugi 画板与 PoC 双向同步**：本地 `.ryugi/artifacts/artboard/` 画板作为交互评审基准，与 `web/src/` 保持增量同步，不在公开仓库提交带私密数据的画板静态文件（详见 [AGENTS.md](../../AGENTS.md)）。
