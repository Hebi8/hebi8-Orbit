## 2. 确立的核心设计原则（踩坑教训）

1. **必须从使用者视角出发，而不是从系统内部实现出发**：
   - 先问「使用者在用这个功能时要做什么、最关注什么、什么才配放在一眼就能扫到的位置」，再决定界面元素。
   - **系统的核心目标是降低使用者的认知负载，而不是把大量状态/过程/计数堆到屏幕上造成信息过载。**
2. **禁止机械照字面实现用户的口语表达（关键教训）**：
   - 用户说「对于一个 session，下面有多少待批我都不在意，给我说当前这个 session 需要注意 或者已经结束就行了」——这是在描述**信息抽象层级与低刺激传达**，**不是**要求把「需要注意」四个字原封不动印满每个标题、卡片、列表和分组（`0b2735f` 就犯了这个错）。
3. **对齐成熟低刺激交互范式**：
   - 固定分栏审阅浮层（左产物、右实时会话）；
   - 低刺激单槽状态传达（静息留白，非静息以克制微标传达优先级）；
   - 左下角精简连接状态底栏。

## 3. 当时 5 项具体反馈与重审要点

| # | 用户原意 / 关注点 | `0b2735f` 已做 | 待重审收口点（已在 v1.1 / v2 完成） |

| 1 | **产出 Review（Code / 设计）**：固定浮窗，左产物右 Session | 删掉可拖动双浮窗，改为固定居中分栏浮层 `ReviewOverlay.tsx` | 核对不同入口打开动线、左侧 Diff/产物阅读密度、右侧会话与左侧产物协作 |
| 2 | **新建线程页**：Tab 内容固定显示，切换不位移 | 去掉选中「项目线程」时动态拼接的文案与内部术语，3 Tab 切换 0px 位移 | 复查整页输入区与底部控件是否还有多余元素或跳转成本 |
| 3 | **PA 页面**：去掉使用时关心的之外的过程信息 | 去掉回复下的内部水位标语与输入框只读声明 | 重审 PA 页、总览页 PA 入口、`⌘K` 三处分工与第一眼信息 |
| 4 | **审批与 Session 状态轰炸**：只传达是否需要介入或已结束 | 按 Session 聚合总览项、去掉侧栏数字角标 | 消除机械满屏打印的「需要注意」字面文字，改为低刺激单槽 `StatusMark` |
| 5 | **左下角主机状态**：日常不关心全网机器明细 | 底栏改为单行连接状态 + 实时延迟，其余节点收进弹窗 | 去掉弹窗内偏实现向的内部字段（如 Runner 版本号） |
